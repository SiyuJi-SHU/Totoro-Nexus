## 最终收尾验收

当前生产链保持轻量：`1200/200` 标题/段落感知切分，按知识库选择向量、BM25 或混合召回，必要时一次跨语言查询，精排后读取命中附近原文，并可按 offset 继续读文。Agent 省略检索 mode 时继承知识库配置，同时绑定多个不同配置的知识库才回退到 hybrid；模型仍可在精确术语场景显式改用 BM25。没有加入 Wiki、GraphRAG、正式父子索引或线上二次 LLM 语义审核。

严格 Chunk ID 用来检查排序稳定性，但相邻 Chunk 或同源原文窗口已经包含答案时仍会判为未命中，因此不能单独代表 Agent 能否回答。Odyssey 同一题集改用 hybrid 后为 `50% / 80%`，低于 semantic 的 `52% / 86%`。Operations 的重复运行中 Hit@1 会在 88%–92% 间波动，但 hybrid 的 Hit@10、候选和两类证据覆盖持续为 100%。这证明模式应按知识库用固定 Case 与完整指标选择，不能把 hybrid 硬设为所有资料的统一答案，也不能只追逐一次 Hit@1。

本次最终回归还修复了一个通用窗口边界缺陷：旧实现会为了对齐段落结尾，无条件退回到 6,000 字上限前的最后一个空行；长段落可能因此丢掉一两千字符。现在仅在边界距离上限 400 字以内时回退，否则保留完整窗口，不增加上下文上限和模型调用。瑙西卡娅等待地点 Case 的目标 Chunk 仍发生 rerank loss，但扩展窗口证据由未覆盖变为覆盖，真实 Agent Run `94e54430-c2cf-412d-aecd-b32c16b3be3b` 及正式评测 Run `94af3130-4bd2-4bce-8630-fad7251f2c96` 均用一次 semantic 检索正确回答白杨树林、井、草地和距离。

`逐字标注覆盖` 要求回答引用包含 Case 保存的整段原文；回答可能引用同源的更小、直接支持结论的段落，因此它是严格字符串诊断，不等于可信率。可信引用由独立评审逐条检查，也仍只是辅助信号。

最终 Odyssey 的 3 个 error 都是供应商 `DataInspectionFailed`，并且全部集中在第十二卷同一段涉及饥饿、牲畜和宰杀的原文上下文；平台已准确区分为上游内容审核，未误报为召回失败。5 个 ungraded 是独立评委调用未完成，不计入通过分母。其余 42 个完成评审的 Case 全部通过。Operations 50 个 Agent Run 全部完成；48 个评审全部通过，2 个仅未完成辅助评审。这个结果证明当前链路有效，但不代表可绕过模型供应商策略或保证未知资料零失败。

## 仍存在的边界

跨语言别名的粗排漏召回、全书综述的覆盖、模型自主查询改写和服务商内容审核仍可能造成失败。这次修复的是通用结构缺陷，不能承诺未来任意知识库零错误。发布后应继续用新文档样本评测；需要更高召回时，应在同一题集下验证查询扩展或更合适的多语言模型，而不是直接提高分数或放宽证据校验。

当前备份与回退方式见 [部署说明](deployment.md)；历史升级草案保留在旧 Project 归档中。

## 本轮协议与状态补充

- ReAct 按规范化参数识别重复调用；有新请求后重置连续重复计数。模型读文必须指定 offset，结果返回 nextRead、newChars 和原文范围，Plan 同样使用该参数协议。
- 中断且没有证据时直接返回“调查未完成”，不再让模型生成“知识库没有”的猜测；状态 partial。
- 工具向模型明确给出窗口引用 ID，documentId/version 只用于读文。保留错填文档 ID 的失败记录；修正提示后新领域三问通过。没有将任意文档 ID 静默映射成证据。
- 正常回答只执行确定性引用校验、同源引用修正和数字/命令约束；不会再把第二次 LLM 语义审核放进用户请求主链。评测 05 的标注审核与 Agent 运行隔离。
- 05 审核未完成的案例不计为可信通过；无适用引用的不计入该分母。页面不再把 null 的可信率回退显示成证据覆盖率。
